# Offline linkage of investigations to spike events

Run from the repository root with the project interpreter and `-m scripts.agent_comparison`. The comparison reads the three 20 November exports and the model dataset identified by the WP03 design hash. Raw files were hashed before and after the run. Row-level linkage and held-out joins are in the ignored versioned derived directory. Published tables contain aggregate comparisons and the mapping audit.

## Linkage rules
An eligible station has one mapped sensor, and that sensor identifies one station in the export. Model metadata must identify a single coordinate pair and agree with the export within 0.0001 degrees on each axis. This conservative choice can lose true station-level matches at multi-sensor sites. Identity failures take priority over out-of-period status, so the outside-period category alone understates all investigations beyond local coverage. Two investigations lacked numeric measurement values; these values are flagged and play no role in matching.

For the primary analysis we aligned the displayed clocks without shifting either and required the investigation timestamp to fall in a candidate hour, from event start inclusive to one hour after its last candidate hour exclusive. We used the spike interval rather than the longer evidence window. A unique pair requires exactly one investigation and one eligible event. Multiple investigations remain in the private audit even when their decisions coincide. The station-hour repetition table counts investigations; the clock sensitivity table counts distinct repeated events. The latter separately counts events receiving both operational decisions.

The export omits timezone, run mode and replay-window duration. Live records may carry their write time and replay records the investigated start time. Neither source time nor a static station map establishes identity of an environmental episode. Applying a two-hour shift in either direction is a sensitivity check, not a calibrated correction. The scenario with the most matches was not selected as truth.

## Interpretation
Of 2,683 rebuilt events, 21 have a unique conditional pair, 33 attract multiple investigations and 2,629 have no eligible overlap at the displayed clock. The primary weak-label by agent table contains nine proxy-real and twelve uncertain events. Only one event also occurs in the held-out model predictions. Each row in the three-way table refers to a model configuration on that same event. Prediction 1 means proxy-real and 0 means proxy-fake.

The 118 reviewed investigations comprise 103 accepted and 15 corrected alerting decisions. All corrections changed no_alert to alert. Four reviewed investigations have unique conditional event links, with three accepted alerts on proxy-real events and one accepted no_alert on an uncertain event. Seven additional reviewed investigations belong to repeated-event groups. None of the four unique reviewed pairs has a held-out prediction. It is therefore impossible to estimate externally validated classifier accuracy from this join. Agent actions incorporate confidence and alerting policy and may use the same neighbourhood evidence as the weak labels.
